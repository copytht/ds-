## Context

- `chat.new`（`src/lib/page.ts` 的 `newChat`）已经用「`[tabindex="0"]` 里文字为『开启新对话』的条目」当锚——真机两态下它都在 DOM，收起时不可见。
- `think.set` / `search.set`（#81 修复后）点完轮询状态到目标、上限 1500ms；侧栏开关同样是前端状态机的一拍，按同口径做。
- 真机 2026-10-07（ds-browser，用户手动收起后只读两态）：
  - **展开**：顶栏容器里 2 颗无字图标键（`ds-button--iconLabelTertiary … --m`）——[搜索 `M11.748…`][侧栏开关 `M9.67272…`]。
  - **收起**：顶栏容器是 1 个无按钮的 spacer + 3 颗无字图标键（`ds-button--iconLabelPrimary … --m`）——
    [侧栏开关 `M9.67272…`][搜索 `M11.748…`][新对话 `M8 0.5996…`]。
  - 侧栏开关两态**图标 path 完全相同**，所以是同一个控件；位置从「2 颗里第 2」变「3 颗里第 1」。
  - 顶栏按钮的父容器（哈希 class）与「开启新对话」条目有共同祖先（侧栏根，类全是哈希）；收起时条目整块 `display:none` 但仍在 DOM；
    11 个会话 `<a>` 同样仍在 DOM 只是不可见。
  - 收起态下 `chat.switch` 照样有效（#76 已验）。
- 身份来源：名字来自 2026-10-06 悬停 tooltip（(198,25) 搜索、(232,25) 收起）；本次用「同图标跨态出现」交叉验证了开关键，没再派悬停事件。
- spec 约束：图标 `path` 不作判据、不碰哈希 class、屏幕坐标不作判据；fail-safe（认不出就 `page-changed`）；ADR-0018（存证先行、用例读存证）。

## Goals / Non-Goals

**Goals:**

- `sidebar.get` / `sidebar.set` 进 v1 名册，四处对齐。
- 数量 / 位置双重校验（组 = 第一颗顶栏图标键的父元素），对不上就停。
- 两态存证入档，回归用例读存证。

**Non-Goals:**

- `sidebar.search`：仍无可靠锚，且点开会弹搜索面板（关面板要派事件）。
- 侧栏里「新对话」按钮：已有 `chat.new`。
- 侧栏滚动 / 会话列表分页。

## Decisions

### 1. 读写成对：`sidebar.get` / `sidebar.set`，不拆 collapse / expand

「一个按钮一个动作」。侧栏开关是一个控件（两态图标同形），拆成两个动作会让两条路对同一个键给出矛盾判断——#32 的教训。
读写成对的形状仓里有先例（`think.get/set`、`button.get/click`）。`set` 带目标态、幂等，agent 不用先问当前是什么态。
**否决**单个 `sidebar.toggle`：不幂等，agent 重试会把它拨反。

### 2. 状态靠「开启新对话」锚的布局盒，不靠开关键或几何

收起时该条目 `display:none`（`getClientRects()` 为空），展开时有盒。这是文字锚上的存在性判断，不碰几何（宽窄 / 坐标）、
不碰图标。**否决**用会话 `<a>` 的可见性判状态：新账号没有会话时会误判为收起。**否决**按开关键图标判状态：图标两态相同，判不出。

### 3. 开关键定位：以第一颗顶栏图标键的父元素为组，数量 + 位置双重校验

两态下开关键都没有任何语义属性，身份只靠「它在顶栏那一组里排第几」。所以：取锚的最近祖先里「无字、带 `ds-button--icon`、
不在会话 `<a>` 内、有布局盒」的图标键（文档序），**以第一颗的父元素为顶栏组**，只数该父元素的直接子里满足同样条件的图标键；
**展开必须恰好 2 颗取第 2、收起必须恰好 3 颗取第 1**。任一不符，当结构变了，`page-changed`、不点——点错的代价是点到搜索（弹面板）或
新对话（开新会话），都不该靠运气。

**真机实测修正（2026-10-07，task 3.2）**：最初写的是「所有这类图标键必须同属一个父元素」，展开态下它**不成立**——最近祖先里还有
会话列表分组标题（「7 天内」）的 22px 折叠小键，父元素不同，会让收起动作在展开态下误判 `page-changed`。改为「以第一颗的父元素为组」。
**否决**按坐标（随窗口宽度变）、**否决**按图标（spec 禁止）、**否决**按 class 末尾哈希（两态不同，改版即失效）。

### 4. 点完等稳定，复用 #81 的口径

侧栏开合有动画与前端状态机，点完立刻读状态会读到旧值。轮询状态、到目标立刻收、上限同 `TOGGLE_SETTLE_MS`。
实现上把 `setToggleOption` 里的「点完轮询」抽成共用小函数（读函数 + 目标态 → 达成态），开关与侧栏共用，不复制第二份。

### 5. 闸：退避，不进 speak

收起 / 展开改页面状态，是写；不动写作框、不发言。与 `chat.new` / `chat.switch` 同。

### 6. 存证 4 条，状态分别记

`sidebar.topbar.expanded`（顶栏容器 2 颗，展开态）、`sidebar.topbar.collapsed`（容器 spacer + 3 颗，收起态）、
`sidebar.toggle.expanded`（展开态的开关键，第 2 颗）、`sidebar.toggle.collapsed`（收起态的开关键，第 1 颗）。
都是 `state-bound`（只在某个态出现）。对账时当前态不符只报「未比」。

## Risks / Trade-offs

- [顶栏还有别的无字图标键混进来（站点加按钮）] → 数量校验会让它直接 `page-changed`，宁可停；存证对账会点名过时。
- [「开启新对话」文字被本地化（只认中文）] → 认不出当控件不在，与 `chat.new` 同一条局限。
- [收起态的 3 颗里新对话键位置若换序] → 开关键取第 1 颗；若站点把新对话挪到最前，会点成新对话——所以存证 + 对账是兜底；
  真机点验时两个方向都验，并读 `chats.list` 数量确认没误开新会话。
- [展开动画期间状态读不稳] → 轮询到目标态就收；上限到了按当时读到的收。
- [合成点击不带用户激活，站点可能忽略] → 真机点验第一项就验，若无效停下改 artifact。
