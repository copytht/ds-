# 子会话可继续：起一次，跨问复用

中继只在第一次问时起一个空子会话，之后每问都往同一个 id 里送，上一轮的问答留给下一轮当
上下文。依据是需求本身：这套东西后期会被**反复调用**——每问起一个新会话的话，第二次调用
跟第一次毫无关系，「在调用同一个子 agent」就是假的。

opencode 原生支持这个形态（同一个 id 反复 `POST .../prompt`），但**忙时再 prompt 不是排队
而是 steer**：新问题被插进还没跑完的那一轮里（实测响应体带 `delivery: "steer"`）。所以
「可继续」不是少建一个会话，它连带定了三件每问必做的事。

## Considered Options

- **每问起一个、答完就删**（原状）：每次都是全新上下文，只用到了「能跑」这一半；反复调用
  每次都得把背景重讲一遍。
- **每问起一个、不删**：会话列表按问句数量往上涨，而轮次之间仍然没有关联，两个方向都没要到。
- **按页面会话各起一个**：上下文不串味，但 `/ask` 的请求体只有 `question` 一条，要按会话
  隔离得先把页面会话 id 一路带过来（channel / background / server / client 四处改）。眼下
  的用法是单会话反复委派，先按「一个中继一个子会话」走，需要隔离时再把那个 key 送上来。
- **只做「不删」，不管排队与等空闲**：必撞 steer，第二问被插进第一轮里——真机实测必现，
  不是理论风险。

## Consequences

- **每问开场三件事**：排队（一把锁，一个 id 同时只接一轮）、等空闲（复用前
  `POST .../wait`，等不到就掐掉那一轮）、掐尾巴（这轮没答成就
  `POST .../interrupt`，子会话本身留着）。三件事都只动子会话，主对话与页面谁都不碰。
- **角色框分两种**：首问 `CHILD_ROLE`（空着出生）、续问 `CONTINUE_ROLE`（已经有上文）；
  子会话换了新的就退回首问那个框。
- **等空闲也有个界**：复用时先 `POST .../wait`，超时窗口就是这一问进门划的静默窗口
  （`DSB_IDLE_TIMEOUT`）——窗口一到就掐掉那一轮继续，不让上一轮的尾巴把这一问永远堵住。
  超时怎么算见 ADR-0006（按静默，不按墙钟）。
- **活期间不删，收摊才删**：Ctrl-C 走 `finally`，SIGTERM 也接到同一条路上——否则每被
  `pkill` 一次，会话列表里就留一条没人删的孤儿。
- **会话没了要认得出**：复用前先 `GET` 一遍，**4xx 才当「没了」**重起一个；5xx 与连不上
  照原样折成故障分支，别把服务故障误判成会话丢失而白起一个子会话。
- **已知天花板**：一个中继进程一个子会话，跨页面会话共用上下文。要按页面会话隔离，
  得让扩展把页面会话 id 送进 `/ask`（见 Considered Options 第三条）。
