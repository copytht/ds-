# ADR-0027: `read` 那四个上限从大到小扫着定，不拍

- **Status**: accepted
- **Date**: 2026-10-08
- **Supersedes**: none

本篇**只补 ADR-0026 的未验证项**：形状已经定了（按行翻页、带行号、三态脚注），**数值
还没定**，而数值不能拍。ADR-0026 **不因此改动**。

## 问题

ADR-0026 落形状时写了四个数：`WORK_READ_PAGE_LINES = 200`、
`WORK_READ_MAX_LINES = 2_000`、`WORK_READ_LINE_LIMIT = 500`、`WORK_READ_BYTES = 16_000`，
扩展侧 `MAX_RESULT_CHARS` 与 `WORK_READ_BYTES` 对齐成 16_000。

**这些是从算术推出来的，不是量出来的。** 推导只有一步：一个源文件行均约 50–60 字，加
行号前缀约 65 字/行，于是 200 行 ≈ 13K 字、100 行 ≈ 6.5K 字。

而真正的问题**不是**「一页多少字装得下」，是「**模型拿到一页之后还读不读得进去**」：

- 页给大了：模型一次吃 13K 字，会不会就不细看、也不翻页了？
- 页给小了：会不会翻到烦了就不翻了（每轮上限 8 轮，ADR-0015）？

这两个只有真机能答。DSH 的 2000 行是**它**在 245K★ 的仓里跑出来的默认，不是我们的答案。

## 决定

**数值待实测，本篇记的是扫法与判据。**

从大到小扫（宽松的先试，才知道天花板在哪）：

| 档  | 每轮总额（扩展侧） | 单次预算（dsb） | 单页默认 |
| --- | ------------------ | --------------- | -------- |
| 1   | 16,000             | 16,000          | 200 行   |
| 2   | 8,000              | 8,000           | 100 行   |
| 3   | 4,000              | 4,000           | 50 行    |
| 4   | 2,000              | 2,000           | 25 行    |

**每档量三样**（缺一不可——只看成本会把「模型读得进去」这个真问题漏掉）：

1. **成本**：那一轮工具结果的**实际字符数**（从扩展侧 `truncateResult` 的入参长度直接读，
   不用估），以及是否触发了这一层的截断。
2. **模型行为**——这是关键：**它会不会用脚注给的 `offset` 翻页**？页给小了会不会反复
   翻（翻到烦了就停）？页给大了会不会一次读完就不细看？
3. **失败痕**：这一档有没有冒出 `key-mismatch`、`shape-unknown` 之类与截断相关的错。

**用什么文件**（三种形状各一份，否则量到的只是巧合）：

- `dsb/work.py`（本仓自己，约 640 行，天然需要翻页）；
- `README.md`（中等，人写的散文）；
- 一个短文件（页比文件还大——这一档该看到「文件读完」而不是「接着读」，验证脚注三态
  在真机上不误导）。

**顺带量一件 ADR-0026 没验的事**：脚注里那句「接着读：offset=N」**到底有没有被用过**。
若从头到尾没有一次翻页，那这套形状的收益只剩成本，Q2 那个三态脚注就是白写的——**这是
本扫法最该先看的一个数**。

## Considered Options

- **照 DSH 的 2000 行取用**：那是它的仓、它的模型、它的负载。对 13K 字的结果，
  DeepSeek 网页模型读不读得进去是未知的——**抄数值不是照抄形状**。否决。
- **按 token 数定而不是字符数**：更贴近模型真实的上下文代价，但本仓所有限额都是字符口径
  （ADR-0014/0016），单开一套会多出一条换算链。否决。
- **一次定死不复扫**：省一轮时间，但代价是把一个未答的问题写进 ADR——ADR-0026 已经这么
  干过一次（本篇是它的补丁），不能再叠。否决。
- **不扫，直接用算术值交付**：那是 ADR-0026 现在的状态，判据「模型读不读得进去」完全没
  答。否决。

## Consequences

- **ADR-0026 的四个数在扫完之前是临时的。** 扫完修订 ADR-0026 的那一节，本篇记结果。
- **扫法本身会留在仓里**：判据（三样都量）与文件选型（三种形状）下次再调 `read` 的
  预算时还能用。
- **可能扫出的结论是「当前值就对了」**——那也要写下来，而不是「扫了几轮没发现更好的」。
  没量过与量过没变化是两件事。

## 未验证项

- **本篇没有真机数据**：四档一个都没跑，上面全是扫法。
- 扫动要动用户的 DeepSeek 账号（发问、等模型排围栏、翻页），跑前要用户点头。
- 「模型会不会翻页」这一项**怎么量**还没定：读它的下一轮围栏里 `read` 的 `offset` 变没变？
  还是读失败痕？前者更直接（`sendCalls` 那一轮的围栏正文），但要在页面里捞——未验可行。
