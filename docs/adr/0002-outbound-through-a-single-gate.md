# 所有出站经唯一出站口，开窗 3~5 秒

扩展往页面发的每一条消息都要过同一个出站口，窗口开启时一次性发出，窗口之间随机等 3~5 秒；不逐条连发、不做固定短间隔的节流。

依据是 2026-09-26/28 的实测（原 issue #8）：一轮 7 次工具执行产生 6 条回灌，**每条间隔都合规**（3.8s/5.0s/3.7s/3.4s/2.3s/15.4s），末尾仍然撞上 `finish_reason: rate_limit_reached`，模型的收尾回答被整个吃掉，随后账号被阶梯处罚禁言 3 天。结论是：**节流合规 ≠ 不会被限流，减少消息条数本身是独立的必要措施**——所以真正的单位是"发了几条"，不是"隔了多久"。

## Considered Options

- **逐条发送 + 固定间隔**：实测已证伪，间隔合规照样撞限流。
- **三态状态机**（正常 / 长休 / 退避，处理阶梯处罚）：旧设计需要它，是因为一轮会发 7 条；现在单来回恒为 1 条，状态机没有负载支撑，押后到真撞限流再做。
- **不节流**：账号已在阶梯处罚区，代价是实测付过的。

## Consequences

- 出站口是扩展里唯一的发送路径，`CONTEXT.md` 的「唯一出站口」与「出站窗口」两条词条即由此而来；新增发送需求只能排进队列，不能绕开。
- 单来回下队列恒只有一个元素，**用户插话与在途回灌的顺序**（旧 `#8` 的 user story 18）押后到支持多块时再定。
- 合并后的消息更长，**站点是否对单条消息长度另有判据**未实测（原 `scripts/cdp-maxlength.mjs` 已随历史清除，需要时重建量法）。
