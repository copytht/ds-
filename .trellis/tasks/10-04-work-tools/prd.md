# dsb 内建工作工具：root 内 ls/read/grep/write/edit

## Goal

给**网页模型**（当子 agent 用的那一半）一套能动手改本机文件的工作工具，让链子从"只会调
第三方工具"变成"能在本机读写代码"。五件：`ls` / `read` / `grep` / `write` / `edit`，
全部钉死在一个可配的**工作文件夹 root** 内。

用户价值：网页模型被派活后，能自己看代码、改代码，而不必每一步都等人喂。

## Background

- 链路（ADR-0011）：网页模型排 ` ```send ` 围栏（一段 `{"tool":…,"arguments":{…}}`）→
  扩展 → `POST /mcp` → dsb → MCP servers（stdio）；结果按 TOON 回灌进对话。
- **工具目录**由 dsb `tools/list` 汇总，喂进扩展的**协议说明**（`src/lib/instructions.ts`）；
  模型照目录选工具，排目录外名字当场报错。
- 扩展侧只过滤 `said_` 前缀（`entrypoints/background.ts:533`）——其余工具**原样进目录**，
  所以 dsb 新增的工具会自动出现在协议说明里，**扩展侧零改动**。
- 自家工具现状：只有 `said_add`/`said_read`（`dsb/server.py:53-72`），且**不进**模型目录。
- dsb 现有约束（ADR-0011）：*"dsb 自己一条工具都不编（除却 said_* 那两件自家小事）"*、
  "被动到底、无状态"。**本任务按用户拍板作废"不编工具"这一条**（见 Decisions）。
- 旧四件套（issue #4，已随大砍移除）：` ```SHELL `/` ```read `/` ```write `/` ```edit `，
  相对路径按 host cwd、16k 截断、`edit` 旧串须唯一命中。`native/host.mjs` 已不存在。
- **权限票 issue #6 = CLOSED / `needs-info`**，关闭语要求恢复工具能力时按新形态重问五问——
  本任务正是触发条件，五问已在 Decisions 逐条答完。

## Requirements

- 五件工作工具，**进模型目录**（不像 `said_*` 被过滤）：`ls` / `read` / `grep` / `write` / `edit`。
- **无命令执行**（SHELL 不提供）。
- 全部动作钉死在**工作文件夹 root** 内：路径解析后必须落在 root 内，越界一律拒绝。
- root **可配**（`.env` / 环境变量 `DSB_WORK_ROOT`），**默认本仓根**。
- 写护栏只一条：**拒写 `.git/` 内**。
- 工具逻辑与 ds- 内部**解耦合**：做成独立模块（纯函数 + 薄适配），单独可测、可换实现。
- 只动 dsb（Python）侧；扩展侧不改。

## Decisions

issue #6 五问 + 落地形态（均由用户拍板）：

- **边界**：钉死一个工作文件夹 root；相对路径以它为基准，越界够不着。
- **SHELL**：**不给**。任意命令天生能越界，与硬边界冲突。连带后果：探索（列目录/搜索）
  改由文件工具 `ls`/`grep` 承担。
- **越界怎么办**：路径必须 `resolve()` 后落在 root 内（跟符号链接、挡 `..`），越界**拒绝并回
  明确错码**，不静默、不截断绕过。
- **相对路径基准**：root。
- **读写是否分档**：root 内读写一视同仁，**只拒写 `.git/`**（结构护栏，不是敏感名单）。
- **打包形态**：**dsb 内建**（用户拍板；ADR-0011 的"不编工具"一条作废，需补 ADR）。
- **解耦**：五件工具自成模块，dsb 只在 `build_tools` 一处挂上。

## Acceptance Criteria

- [ ] dsb 的 `tools/list` 含 `ls`/`read`/`grep`/`write`/`edit`，各自描述写清"工作目录内"，
      且不含任何命令执行工具。
- [ ] 网页模型的协议说明目录里列出这五件（扩展侧零改动能出现）。
- [ ] `read` 能读 root 内文件并回灌正文；超长按上限截断并标注。
- [ ] `write` 能在 root 内新建/覆盖文件；`edit` 旧串**唯一命中**才改，0 处/多处回明确错码且
      **文件不变**。
- [ ] `ls` 列 root 内某目录、`grep` 搜 root 内内容，各有上限。
- [ ] 传 root 外路径（含 `..` 与符号链接逃逸）→ 回 `out-of-root`，**不碰文件**。
- [ ] 写/改 `.git/` 内 → 回 `protected-path`，**不碰文件**。
- [ ] root 默认=仓库根；`DSB_WORK_ROOT` 改得动；root 不存在时拒绝并说清。
- [ ] 未配/未起 dsb 时，扩展照旧显示"工具表暂未取到"，行为不变。
- [ ] `pnpm quality` 全绿（ruff + pytest + 静态守卫）；新增单测覆盖路径解析（in/out/`..`/
      符号链接）、五件行为、截断、`.git` 护栏、`edit` 唯一性、各错码。

## Out of Scope

- 命令执行 / SHELL / 真 OS 沙箱（截 SHELL 就是为回避它）。
- root 之外的任何读写。
- 扩展侧 UI：工具开关、目录编辑、协议说明里对工作工具的特殊提示（靠工具描述自带）。
- 第三方 / 远程 MCP server 的发现与注册（那是"工具目录/MCP 生态"另一条轴）。
- 协调者 → 网页派活、网页 → 协调者结构化交活（本次未选）。
- `said_*` 的任何改动。
