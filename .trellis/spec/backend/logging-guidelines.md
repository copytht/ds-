# 日志与留痕

## 失败留痕的口径（ADR-0004）

- **只记事件，不记正文**：入参与结果正文都没有进入签名的位置。
  留痕回答「几点红的、哪个环节、什么原因、多久自己绿的」，不回答「说了什么」。
- 中继侧：`dsb/log.py` 的 `log_event` 一行事件（`bad-request` / `mcp-broke`；
  工具层 `tool-fail` / `tool-slow` 在 `dsb/mcp.py`）。
- 扩展侧：`storage.local` 的 `ds-/failures`（`src/lib/failurelog.ts`）。
- 访问日志整个关掉；不要重新打开。

## 写日志的规矩

- 事件名是名词性的短横线词（`tool-fail`、`bad-request`），新事件名跟 `log_event`
  的既有调用点看齐，先想「这是事件还是正文」。
- 日志里**不写**：工具入参、工具结果、回灌文本、账号详情。
- 慢与坏要分得清：`tool-slow`（超 `tool-timeout` 口径）与 `tool-fail`（结果带错）
  是两笔账。

## 反模式

- 在网关里加「完整请求日志」或打印 payload——直接破 ADR-0004。
- 把留痕当通信通道（「日志里看到了就能知道结果」）——结果只走回灌。
- 给扩展侧失败提示加正文——失败提示不进对话流（ADR-0010）。
